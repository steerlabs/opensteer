# Research & Prototype: Bringing Tabs Back on Opensteer's Linux Browser Runtime

**Target commit base:** `4910b97d7` (branch `linux-tab-restore`)  
**Chromium build tested:** Google Chrome for Testing `151.0.7922.34` (Playwright `1.62.1`, revision `1234`, `chrome-mac-arm64`)  
**Prototype & evidence directory:** `experiments/linux-tab-restore/` (`run-matrix.mjs`, `run-memory.mjs`, `probe-hybrid-extension.mjs`, `matrix-results.json`, `memory-results.json`, `hybrid-extension-results.json`)

---

## Executive Recommendation

Adopt **Hybrid C + B**: use **Chromium's native tab discarding (Option C)** for sleeping tabs — driven by `--disable-field-trial-config --enable-features=WebContentsDiscard` plus a ~50-line bundled MV3 lifecycle helper extension (`permissions: ["tabs", "debugger"]`, zero host permissions, zero content scripts) that calls `chrome.tabs.discard(tabId)` after `Page.setWebLifecycleState("frozen")` flushes Blink `PageState` and Opensteer detaches CDP — paired with **Chromium's native session restore (Option B)** for cold browser restarts, by removing `--no-startup-window`, preserving `Default/Sessions/{Session_*,Tabs_*}`, normalizing `profile.exit_type` after hard kills, and matching restored tabs to Home surfaces deterministically via the helper extension's `TabStripModel` `index` + `chrome.debugger.getTargets()` `targetId` (without waking unloaded tabs). Both sleep and cold restart then run on Chromium's own `NavigationController` + Blink `PageState` + `SessionStorageNamespace` machinery — restoring scroll position, native form controls, full back/forward stacks with `history.state`, and `sessionStorage` before load scripts, while freeing 100% of discarded renderer processes (`~1.8 MiB` marginal total RSS per discarded tab across 70 tabs; `~44–55 ms` local wake) and letting Chromium's `BackgroundTabLoadingPolicy` defer 66 of 70 tabs on cold restart.

**Strongest argument against this design:** It depends on two Chromium desktop internals that are not part of CDP: (1) loading an unpacked MV3 helper extension (`--disable-extensions-except=<dir> --load-extension=<dir>`) and (2) enabling `--enable-features=WebContentsDiscard` (currently enabled by default on Android and in Chromium's field-trial testing config, not yet default-on on desktop Linux) while disabling field-trial configs (`--disable-field-trial-config`). A future Chromium bump could change `WebContentsDiscard` flag names or tighten `--load-extension` (Chrome branded builds removed `--load-extension` in M137, though Chrome for Testing / unbranded Chromium explicitly retains it), and `chrome.tabs.discard` + Session Restore never recover `contenteditable` edits, in-memory JS/canvas state, playing media position, password fields, or POST response bodies without user confirmation — whereas Option A can recover simple `contenteditable` text (at the cost of losing real history/SPA state and breaking on cold restarts). The fallback if `WebContentsDiscard` ever regresses is clean: default (non-WCD) `chrome.tabs.discard` already works with identical fidelity and memory savings, requiring only a `targetId` remap from `chrome.debugger.getTargets()` on discard.

## 1. Today on Linux: Exact Behavior (Code + Empirical Evidence)

### 1.1 Slept tab today
1. **No `captureRestore` on Linux:** `PlaywrightPageHandle` in `apps/browser-runtime/src/browser/playwright-launcher.ts:1058` does not implement `BrowserPage.captureRestore()` (`packages/browser-runtime-core/src/browser/backend.ts:76`), and `PlaywrightContextHandle.createPage()` ignores `options?.restore`. (Contrast Mac Electron: `apps/desktop/src/browser/electron-browser-launcher.ts` + `apps/desktop/src/browser/page-restore.ts` capture up to 1 MiB of Electron `navigationHistory` entries with Blink `pageState` plus up to 256 KiB of `sessionStorage` seeded via preload IPC `opensteer:wake-seed` before document scripts run.)
2. **Destroy-and-navigate sleep/wake:** When `SurfaceLedger.sleep()` (`packages/browser-runtime-core/src/browser/surface-ledger.ts:498-575`) puts a Linux tab to sleep, `captureRestore` is absent, so it stores `{ url: record.url, engine: null, bytes: 0 }` (line 552), calls `detachLive(record)`, and calls `pages.destroy(live.page, "slept")` (`page.close({ runBeforeUnload: false })`). On `SurfaceLedger.wake()` (`surface-ledger.ts:592-620`), `context.createPage()` opens a fresh `about:blank` tab and navigates to `record.url` via `Page.navigate`.
3. **No real renderer memory measurement on Linux:** `PlaywrightChromiumLauncher` does not implement `rendererUsage()`, so `TabSleeper` (`packages/browser-runtime-core/src/browser/tab-sleeper.ts:11-16,120-138`) falls back to the heuristic `livePages * 100 MiB + hosts * 150 MiB` against a budget of `clamp(25% of container RAM, 2 GiB, 8 GiB)` — which equals **2 GiB** in `deploy/home/compose.yaml:174-175` (`mem_limit: 4g`, `memswap_limit: 4g`, zero swap). At ~19–20 live tabs, `TabSleeper` starts sleeping background tabs.
4. **Empirical baseline (`matrix-results.json` → `baseline`):** Closing and reopening by URL lost **100%** of tab state across all 7 fixture types: `scrollY: 3200 → 0`; all form fields (`text`, `textarea`, `select`, `checkbox`, `password`, `contenteditable`) reset to defaults; SPA history collapsed from 5 entries (`history.state = {step: 3}`) to 2 (`["about:blank", "/spa/step-3"]`, `state: null`, Back goes to `about:blank`); `sessionStorage` cleared (`null`); POST `/post-result` silently downgraded to a fresh `GET /post-result` (new server nonce, empty body); `beforeunload` draft lost; audio reset to `paused: true, currentTime: 0`.

### 1.2 Cold Linux Chromium restart today
1. **Session files explicitly deleted before every launch:** `initializeNativePreferences()` (`apps/browser-runtime/src/browser/native-profile-storage.ts:13-27`) unlinks every `Session_*`, `Tabs_*`, `Current/Last Session`, and `Current/Last Tabs` file in `<profile>/Default/Sessions/` before Chromium starts.
2. **Hidden-window launch rejects any restored page:** `launchNative()` (`apps/browser-runtime/src/browser/playwright-launcher.ts:598-617`) passes `--no-startup-window --restore-last-session`. `--restore-last-session` is passed **solely** so Chromium persists session cookies (`restore_on_startup: 1` in `Default/Preferences`); `--no-startup-window` prevents Chromium from creating a browser window or restoring tabs, and `playwright-launcher.ts` throws if `context.pages().length > 0` at startup.
3. **Host durable tabs reopen by URL only:** `apps/host/src/browser/browser-service.ts` persists durable tab descriptors (`url`, `title`, `order`, `openerId`, `favicon`) in PostgreSQL and recreates dormant tabs on demand by opening a new page and calling `Page.navigate(url)`.
4. **What survives a cold restart today:** Profile-level storage only — persistent and session cookies (flushed via `flushNativeCookies()` in `native-profile-storage.ts:74-90`), `localStorage`, `IndexedDB`, Cache Storage, Service Workers, and the Host's tab list (`url`, `title`, `order`, `openerId`). Everything tab-scoped (scroll, forms, back/forward history, `history.state`, `sessionStorage`, POST results, JS heap) is lost.

### 1.3 Critical Chromium `151.0.7922.34` Discovery: Missing `--disable-field-trial-config` Leaks Renderers
While benchmarking Option C and Baseline closes, we discovered an existing bug in how Chromium `151.0.7922.34` behaves under `playwright-launcher.ts:598`:
- `playwright-launcher.ts` sets `ignoreDefaultArgs: true` and **omits `--disable-field-trial-config`** (which Playwright normally passes by default).
- In Chrome for Testing `151.0.7922.34`, omitting `--disable-field-trial-config` activates [`testing/variations/fieldtrial_testing_config.json:24269`](https://github.com/chromium/chromium/blob/151.0.7922.34/testing/variations/fieldtrial_testing_config.json#L24269), which enables **`TrackEmptyRendererProcessesForReuse`** (`TransientKeepAlivePolicy`).
- That feature holds `pending_reuse_ref_count_` (`DelayShutdownReason::kPendingReuse = 7` in [`content/browser/renderer_host/render_process_host_impl.h`](https://github.com/chromium/chromium/blob/151.0.7922.34/content/browser/renderer_host/render_process_host_impl.h)), blocking `FastShutdownIfPossible` and `RenderProcessHostImpl::Cleanup` ([`render_process_host_impl.cc:4439`](https://github.com/chromium/chromium/blob/151.0.7922.34/content/browser/renderer_host/render_process_host_impl.cc#L4439)).
- **Measured impact:** Without `--disable-field-trial-config`, discarding or even closing 70 tabs left **74 renderer processes (~11.6 GiB RSS)** alive! Passing `--disable-field-trial-config` immediately restored fast-kill (`FastKillForDiscard: 3/3 kKilled`) and dropped 70 discarded tabs down to **2 baseline renderers (`932.6 MiB` total RSS)**. Adding `--disable-field-trial-config` to `launchNative()` is essential regardless of which restore option is chosen.

## 2. Evaluation of Options

### Option A — Capture over CDP, Restore by Navigating & Injecting
- **Mechanism:** Before closing a tab, read `Page.getNavigationHistory` and execute a snapshot script via `Runtime.evaluate` capturing `window.scrollX/Y`, `sessionStorage`, and form values (`input`, `textarea`, `select`, `checkbox`, `contenteditable`, excluding `type="password"`). On wake, create a tab, register `Page.addScriptToEvaluateOnNewDocument` to seed `sessionStorage` before page scripts run, navigate to the URL (or replay same-origin `pushState` URLs), and inject scroll/form values on `load`.
- **What it can restore:** Scroll position, `sessionStorage` (before load scripts), standard form inputs, **and `contenteditable` text** (the one field type Blink `PageState` does not save). Snapshot size is tiny (~500–900 bytes per tab in our prototype).
- **What it can never restore:**
  1. **Real back/forward stack & cross-origin history:** CDP `Page.getNavigationHistory` ([`content/browser/devtools/protocol/page_handler.cc:1253`](https://github.com/chromium/chromium/blob/151.0.7922.34/content/browser/devtools/protocol/page_handler.cc#L1253)) returns `{id, url, userTypedURL, title, transitionType}` only — **no Blink `PageState` and no `history.state`**. You cannot inject cross-origin back entries or forward entries without actually navigating to them (causing side effects and broken history), and replaying same-origin `pushState` loses `history.state` for every entry except the current one (verified in `matrix-results.json`: `afterBack.state === null`).
  2. **POST results:** Navigating by URL silently downgrades `POST /post-result` to `GET /post-result` (verified: `method: "POST" → "GET"`, `nonce: "3" → "4"`).
  3. **Framework-controlled / dynamic / Shadow DOM forms:** Re-setting `.value` on React/Vue controlled inputs or lazily mounted SPA views is fragile and misses Shadow DOM unless deeply crawled; `PageState` is restored natively by Blink during HTML parsing.
  4. **Cold restarts:** In-memory snapshots vanish when `browser-runtime` or Chromium restarts; persisting form drafts and `sessionStorage` in Opensteer's own store would add a new sensitive-data surface outside the Chromium profile (`docs/browser-sessions.md:42`).

### Option B — Chromium's Own Session Restore (Cold Restarts)
- **Mechanism:** Remove `--no-startup-window` from `launchNative()`, stop deleting `Default/Sessions/{Session_*,Tabs_*}` in `initializeNativePreferences()`, and launch with `--restore-last-session` and `Default/Preferences` `{"session":{"restore_on_startup":1}}`.
- **Works in headless Chromium `151.0.7922.34`?** **Yes — verified.** With `--headless=new --restore-last-session` and no `--no-startup-window`, Chromium creates a headless browser window, reads `Default/Sessions/Session_*`, and restores every open tab's `NavigationController` entries (up to `gMaxPersistNavigationCount = 6` back + 6 forward per [`components/sessions/core/session_constants.cc`](https://github.com/chromium/chromium/blob/151.0.7922.34/components/sessions/core/session_constants.cc)), Blink `PageState` (scroll + form controls + `history.state`), and `SessionStorageNamespace` (associated via `CreateSessionStorageAssociatedCommand` in [`chrome/browser/sessions/session_service_base.cc`](https://github.com/chromium/chromium/blob/151.0.7922.34/chrome/browser/sessions/session_service_base.cc)).
- **Deferred loading at 70 tabs:** Chromium's `BackgroundTabLoadingPolicy` ([`chrome/browser/performance_manager/policies/background_tab_loading_policy.h`](https://github.com/chromium/chromium/blob/151.0.7922.34/chrome/browser/performance_manager/policies/background_tab_loading_policy.h)) caps eager loads (`kMinTabsToLoad = 4`, `kMaxTabsToLoad = 20`, `kMaxSimultaneousTabLoads = 4`, `kDesiredAmountOfFreeMemoryMb = 150`). In our 70-tab cold restart benchmark, **only 4 tabs loaded (from HTTP cache) and 66 stayed completely unloaded** (`6` total renderers vs `2` baseline; `+20.2 MiB` browser RSS).
- **What happens to closed vs. discarded tabs:**
  - Tabs closed via `Target.closeTarget` (as `TabSleeper` does today) are **removed from `Session_*` and do not come back** (`closedSentinelCameBack: false`). That is why Option B alone cannot recover tabs that `TabSleeper` previously closed — it needs Option C so slept tabs stay in `TabStripModel` as discarded tabs!
  - Tabs discarded via Option C **stay in `Session_*` and come back with full scroll, forms, SPA history, and `sessionStorage`** across a browser restart (`matrix-results.json` → `hybridCPlusB`: 7/7 tabs restored).
- **Hard crash (`SIGKILL` / OOM) gotcha and fix:** On unclean exit, Chromium leaves `Default/Preferences` with `profile.exit_type = "Crashed"`. In [`chrome/browser/ui/startup/startup_browser_creator_impl.cc:460`](https://github.com/chromium/chromium/blob/151.0.7922.34/chrome/browser/ui/startup/startup_browser_creator_impl.cc#L460), `HasPendingUncleanExit()` suppresses automatic `--restore-last-session` and opens an empty `chrome://newtab/` bubble instead! Normalizing `Default/Preferences` (`exit_type: "Normal"`, `exited_cleanly: true`) before relaunch makes Chromium auto-restore all tabs from `Sessions/Session_*` even after `SIGKILL` (verified in `optionBCrash` and `probe-hybrid-extension.mjs`: 7/7 and 5/5 restored). Only mutations within the last ~2.5 s before `SIGKILL` can be missed (`CommandStorageManager::kSaveDelay = 2500ms` in [`components/sessions/core/command_storage_manager.cc`](https://github.com/chromium/chromium/blob/151.0.7922.34/components/sessions/core/command_storage_manager.cc); note `sessionStorage` and a freshly typed `beforeunload` draft in `optionBCrash` were lost when `SIGKILL` hit before the 2.5s flush, whereas waiting 3s in `probe-hybrid-extension.mjs` preserved both 100%).
- **Matching restored targets to Home surfaces without guessing:**
  - **Raw CDP cannot match duplicate URLs:** `Target.getTargets()` returns targets in unordered map order (`orderPreserved: false` in `optionBClean` and `optionBCrash`), and CDP provides no `TabStripModel` index.
  - **Deterministic fix:** Persist a tiny profile-local sidecar `<profile>/opensteer-tabs.json` recording `[{ index, surfaceId, url }]` whenever tabs open/close/reorder. On startup, the MV3 helper extension runs `chrome.tabs.query({})` + `chrome.debugger.getTargets()` (backed by [`chrome/browser/extensions/api/debugger/debugger_api.cc:1012`](https://github.com/chromium/chromium/blob/151.0.7922.34/chrome/browser/extensions/api/debugger/debugger_api.cc#L1012), which emits the exact CDP `targetId` + `tabId` even for `status: "unloaded"` tabs **without waking them**). Sorting by `(windowId, index)` gives a 1-to-1 `(index, url) → targetId` mapping that resolves duplicate URLs unambiguously (verified in `probe-hybrid-extension.mjs`: `surf_dup_A` at `scrollY=1100` and `surf_dup_B` at `scrollY=2900`, identical URL `/article`, matched 100% accurately after `SIGKILL`!).

### Option C — Chromium's Own Tab Discarding (Slept Tabs)
- **Mechanism:** Instead of closing a page to sleep it, discard its renderer while keeping the tab in Chromium's `TabStripModel` with its `NavigationController`, Blink `PageState`, and `SessionStorageNamespace` intact in the browser process (`TabLifecycleUnit::Discard` in [`chrome/browser/resource_coordinator/tab_lifecycle_unit.cc:366`](https://github.com/chromium/chromium/blob/151.0.7922.34/chrome/browser/resource_coordinator/tab_lifecycle_unit.cc#L366)). Waking is just activating or reloading the tab (`Target.activateTarget`).
- **How to trigger discard reliably — 4 mechanisms evaluated:**
  1. **CDP command:** Does not exist in `Page.pdl`, `Target.pdl`, or `Browser.pdl` in Chromium `151.0.7922.34`.
  2. **Chromium automatic policies (Memory Saver / Urgent Discard):** **Unusable for Opensteer.**
     - `MemorySaverModePolicy` ([`memory_saver_mode_policy.cc:201-224`](https://github.com/chromium/chromium/blob/151.0.7922.34/chrome/browser/performance_manager/policies/memory_saver_mode_policy.cc#L201-L224)) uses 2h / 4h / 6h idle timeouts and skips tabs revisited >15 times.
     - `UrgentPageDiscardingPolicy` relies on `SystemMemoryPressureEvaluator::CreateDefaultSystemEvaluator()` ([`components/memory_pressure/system_memory_pressure_evaluator.cc:32-46`](https://github.com/chromium/chromium/blob/151.0.7922.34/components/memory_pressure/system_memory_pressure_evaluator.cc#L32-L46)), which **returns `nullptr` on desktop Linux** (no OS memory-pressure monitor!).
     - Both also call `DiscardEligibilityPolicy::CanDiscard(PROACTIVE/URGENT)` ([`discard_eligibility_policy.cc:176`](https://github.com/chromium/chromium/blob/151.0.7922.34/chrome/browser/performance_manager/policies/discard_eligibility_policy.cc#L176)), which refuses tabs with `IsDevToolsOpen`, `HadFormInteraction`, `HadUserEdits`, or recently visible status (verified in `matrix-results.json`: `canDiscardUrgent: false` on all 7 pages!).
  3. **`chrome://discards` Mojo (`DetailsProvider.discardById(id, EXTERNAL=0)`):** Works (`EXTERNAL` bypasses `CanDiscard` heuristics at [`discard_eligibility_policy.cc:250-254`](https://github.com/chromium/chromium/blob/151.0.7922.34/chrome/browser/performance_manager/policies/discard_eligibility_policy.cc#L250-L254)), **but** Chromium `151` gates debug WebUIs behind `Local State` `{"internal_only_uis_enabled": true}` ([`components/webui/chrome_urls/pref_names.h`](https://github.com/chromium/chromium/blob/151.0.7922.34/components/webui/chrome_urls/pref_names.h)), exposes an unsupported internal Mojo interface, requires keeping a `chrome://discards` tab open, and does **not** return CDP `targetId` (making duplicate URLs ambiguous).
  4. **Tiny bundled MV3 helper extension (`chrome.tabs.discard(tabId)` + `chrome.debugger.getTargets()`):** **Best mechanism.** Loaded with `--disable-extensions-except=<extDir> --load-extension=<extDir>` (keeping all other extensions disabled; `--load-extension` is permanently supported in Chrome for Testing / unbranded Chromium in [`chrome/browser/extensions/extension_service.cc`](https://github.com/chromium/chromium/blob/151.0.7922.34/chrome/browser/extensions/extension_service.cc)). Calls Chromium's public `TabsDiscardFunction::Run` ([`chrome/browser/extensions/api/tabs/tabs_api.cc:4083`](https://github.com/chromium/chromium/blob/151.0.7922.34/chrome/browser/extensions/api/tabs/tabs_api.cc#L4083)), which invokes `Discard(LifecycleUnitDiscardReason::EXTERNAL)`. Zero host permissions, zero content scripts, ~50 lines of JS, and simultaneously solves Option B's `TabStripModel` index ↔ `targetId` matching!
- **Default Discard vs. `--enable-features=WebContentsDiscard` (`kWebContentsDiscard`):**
  - **Default (`FinishDiscard` in [`tab_lifecycle_unit.cc:270`](https://github.com/chromium/chromium/blob/151.0.7922.34/chrome/browser/resource_coordinator/tab_lifecycle_unit.cc#L270)):** Replaces the `WebContents` with a null `WebContents` via `NavigationControllerImpl::CopyStateFrom()` ([`navigation_controller_impl.cc:3027`](https://github.com/chromium/chromium/blob/151.0.7922.34/content/browser/renderer_host/navigation_controller_impl.cc#L3027)). **Consequence:** emits `Target.targetCreated` (new `targetId`) + `Target.targetDestroyed` (old `targetId`), `targetIdPreserved: false`, and SPA Back after wake triggers a full document reload (`GET /spa/step-2`) rather than same-document `popstate`.
  - **With `--enable-features=WebContentsDiscard` (`FinishDiscardAndPreserveWebContents` in [`tab_lifecycle_unit.cc:342`](https://github.com/chromium/chromium/blob/151.0.7922.34/chrome/browser/resource_coordinator/tab_lifecycle_unit.cc#L342) → `WebContentsImpl::Discard` in [`web_contents_impl.cc:2671`](https://github.com/chromium/chromium/blob/151.0.7922.34/content/browser/web_contents/web_contents_impl.cc#L2671) → `FrameTree::Discard`):** Discards the renderer frame in place without replacing `WebContents`. **Verified results (`matrix-results.json` → `optionCWcd` & `hybrid-extension-results.json`):**
    - **`targetId` and `tabId` are 100% preserved** (`targetIdPreserved: true` across 7/7 tabs; zero `Target.targetDestroyed` / `Target.targetCreated` churn!).
    - **Identical memory savings** (`4` renderers, `1177.8 MiB` total RSS — identical to closing all 10 tabs at `1179.9 MiB`).
    - **Even better SPA Back fidelity:** SPA Back fired same-document `popstate` with `{step: 2}` and **zero network request** (`popEvents: [{path: "/spa/step-2", state: {step: 2}}]`)!
- **Two Critical Production Subtleties Proven in Our Prototypes:**
  1. **Detach CDP before discarding:** Under `WebContentsDiscard`, discarding while a CDP session is attached succeeds (`ok: true`) **without** emitting `Target.detachedFromTarget`, and subsequent `Runtime.evaluate` calls on that stale session hang until timeout (`hybrid-extension-results.json`: `detachedEventSeen: false`, `evalAfterDiscardErr: "CDP timeout (15000ms): Runtime.evaluate"`). Opensteer's `SurfaceLedger.sleep()` already calls `detachLive()` before sleeping — that ordering is mandatory.
  2. **Freeze immediately before detach + discard to flush Blink `PageState`:** `AttemptFastKillForDiscard()` ([`chrome/browser/resource_coordinator/utils.cc:33`](https://github.com/chromium/chromium/blob/151.0.7922.34/chrome/browser/resource_coordinator/utils.cc#L33)) fast-kills the renderer before Blink's asynchronous `StartDelayedSyncTimer` ([`content/renderer/render_frame_impl.cc:4365`](https://github.com/chromium/chromium/blob/151.0.7922.34/content/renderer/render_frame_impl.cc#L4365)) flushes recent scroll/form updates. Without freezing first, `surf_dup_B` lost `scrollY: 2900 → 0` and rapid-batched tabs in `run-memory.mjs` lost `scrollY` and `field`. Adding **`await cdp.send("Page.setWebLifecycleState", { state: "frozen" })`** immediately before detaching and discarding forces `RenderFrameImpl::SendUpdateState()` synchronously ([`render_frame_impl.cc:4340`](https://github.com/chromium/chromium/blob/151.0.7922.34/content/renderer/render_frame_impl.cc#L4340)), restoring `surf_dup_B`'s `scrollY: 2900` 100% reliably (`hybrid-extension-results.json` after fix: `expectedScrollY: 2900, actualScrollY: 2900`).

### Option D — Freezing (`Page.setWebLifecycleState("frozen")`) + Swap/zram
- **Mechanism:** Keep all 70 renderers alive, call `Page.setWebLifecycleState({ state: "frozen" })` ([`page_handler.cc:1872`](https://github.com/chromium/chromium/blob/151.0.7922.34/content/browser/devtools/protocol/page_handler.cc#L1872) → `WebContentsImpl::SetPageFrozen`) to stop timers/JS/media, and rely on Linux swap or zram to evict frozen renderer anonymous pages from RAM.
- **Measured reality:**
  - **Best in-memory fidelity & wake speed:** 100% of JS heap, DOM, `contenteditable`, passwords, POST response, and media seek position (`0.363s`, paused) survive with **0.4 ms median wake latency** and **0 network requests**.
  - **Zero RAM freed without swap:** Freezing 10 tabs changed OS RSS from `2601.55 MiB` to `2611.91 MiB` (**`+149 MiB/tab` still resident**; `+114 MiB/tab` private footprint).
  - **Zero help for cold browser restarts:** When Chromium restarts after 24h asleep, update, or "Restart browser", every frozen renderer dies; Option B is still required.
  - **Container requirements & risk:** `deploy/home/compose.yaml:174-175` sets `mem_limit: 4g` and `memswap_limit: 4g` (**zero swap allowed**). To make Option D free RAM, the Cloud Computer host/VM must provision a zram or disk swap device AND raise `memswap_limit` (or cgroup v2 `memory.swap.max`). Even with 2:1–3:1 zram compression, 70 real renderer processes (typically 100–200 MiB private each = 7–14 GiB uncompressed) still consume **2.5–5 GiB of compressed RAM inside zram** (plus kernel page-table/process overhead) — risking OOM under a 4 GiB container limit and adding page-fault latency on wake (exact Linux zram/swap numbers are **unverified** on this macOS host).

## 4. Memory & Wake-Timing Measurements

### Methodology
- **Script:** `experiments/linux-tab-restore/run-memory.mjs` (`memory-results.json`), run on macOS arm64 against Chrome for Testing `151.0.7922.34` with `--headless=new --disable-field-trial-config`.
- **Workload:** Each tab loads `/heavy?mb=4&label=tab-N` on a **distinct origin** (`http://site-N.localhost:<port>`) so Chromium's Site Isolation spawns one renderer process per tab (each holding a 4 MiB JS `Uint8Array` + 250 DOM cards).
- **Metrics:**
  - **OS Process-Tree RSS (`ps -axo pid,ppid,rss,command`):** Exact resident memory across the browser PID and all descendants, broken down into total, browser process, and renderer processes. This is the authoritative measurement of what actually left RAM.
  - **Chromium `privateFootprintKb` (`chrome://discards/graph`):** Recorded alongside RSS; note that PerformanceManager only refreshes OS memory dumps periodically (~2 min) rather than synchronously on discard, so its `privateFootprintKb` lagged after rapid discards while OS `ps` immediately showed renderer processes exited (`14 → 4` and `70 → 2`).
  - **Wake latency:** Wall-clock time from `Target.activateTarget` (or `Page.setWebLifecycleState("active")` / `Target.createTarget` + `Page.navigate`) until `document.readyState === "complete"` on localhost (excludes real WAN RTT).

## 5. Fit with Opensteer's Existing Architecture

### 5.1 Meeting `BrowserPage`, `SurfaceLedger`, and `TabSleeper`
Today's seam (`packages/browser-runtime-core/src/browser/backend.ts:74-158`) assumes a **capture-and-destroy** sleep model built for Mac Electron (`captureRestore()` → `pages.destroy(page, "slept")` → `context.createPage({ restore })`). Option C on Linux keeps the `WebContents` alive in Chromium's `TabStripModel` and discards its renderer in place.

There are two clean ways to meet the existing seam; the second is far cleaner:
1. **Optional native-discard hooks on `BrowserPage` (`backend.ts`)** — add two optional methods alongside `captureRestore?()`:
   - `discard?(): Promise<void>` — freezes (`Page.setWebLifecycleState("frozen")`), detaches the page's CDP session (after `SurfaceLedger.detachLive()`), and calls the helper extension's `discardByTargetId(targetId)`.
   - `wakeDiscarded?(): Promise<void>` — activates the discarded target (`Target.activateTarget`) so Chromium reloads its `NavigationController` + `PageState` + `SessionStorageNamespace`, then re-acquires `page.cdp()` and re-runs `SurfaceLedger`'s `registerOnce` initialization (`Page.enable`, `applyMetrics`, `refreshNavigation`).
2. **What stays 100% shared between Mac Electron and Linux:**
   - **All `TabSleeper` policy and scheduling** (`tab-sleeper.ts`): budget hysteresis, LRU/category ordering, quiet/leftover/readIdle deadlines, backoff, and **every blocker** (`typed`, `post`, `upload`, `media`, `download`, `dialog`, `loading`, `opener`, `viewed`, `pinned`, `operation`, `demanded`). Linux keeps all of these protections intact — including `post` and `media`, which directly protect the two page types Chromium discard cannot silently restore!
   - **All `SurfaceLedger` lease & tab state transitions** (`TabLease`: `live → sleeping → suspended → waking → live`). During `suspended`, a discarded Linux tab has `record.live === null` (no CDP session attached, invisible to `SessionCdpRouter` agent commands until woken) while `SurfaceLedger` holds a lightweight `discardedPage: BrowserPage` handle instead of `restore.engine`. On `closeSurface()`, it closes that discarded tab (`Target.closeTarget`) so Chromium removes it from `Default/Sessions/Session_*`.
   - **Real memory measurement on Linux:** Implement `BrowserLauncher.rendererUsage()` on `PlaywrightChromiumLauncher` by reading `/proc/<pid>/status` (`VmRSS` / `RssAnon`) or `SystemInfo.getProcessInfo` + Linux `/proc/<pid>/smaps_rollup` (`Pss` / `Private_Dirty`) for child renderer PIDs of `ownedProcess.pid`. That replaces the crude `100 MiB/page` estimate in `TabSleeper` with exact renderer memory against the container's `process.constrainedMemory()` (`4 GiB` → `2 GiB` floor, or tunable for Cloud Computers).
3. **What differs cleanly between Mac and Linux:**
   - **Mac Electron** continues using `captureRestore()` + `WebContents` destroy/recreate (`page-restore.ts`), because Electron's `WebContentsView` architecture has no `TabStripModel` or `chrome.tabs.discard`.
   - **Linux Chromium** uses native `discard()` / `wakeDiscarded()` + Chromium `--restore-last-session` on cold start.

### 5.2 Cold Restart & Host Tab Reconciliation
- **Profile sidecar `<profile>/opensteer-tabs.json`:** Written atomically (write temp + rename) whenever `SurfaceLedger` opens, closes, or reorders durable tabs in a native profile: `[{ index, surfaceId, url }]`.
- **On cold Chromium launch (`launchNative()`):**
  1. Remove `--no-startup-window` and stop deleting `Default/Sessions/*` in `initializeNativePreferences()`.
  2. Before launch, read `Default/Preferences`; if `profile.exit_type !== "Normal"` (after `SIGKILL`/OOM/host crash), normalize `exit_type = "Normal"`, `exited_cleanly = true` (leaving `restore_on_startup: 1`).
  3. Pass `--disable-field-trial-config --enable-features=WebContentsDiscard --disable-extensions-except=<extDir> --load-extension=<extDir>`.
  4. Wait for the helper extension's service worker and call `inventory()` (`chrome.tabs.query({})` + `chrome.debugger.getTargets()`), returning every restored tab's `{ index, tabId, targetId, url, status, discarded }` **without waking unloaded tabs**.
  5. Match restored tabs against `opensteer-tabs.json` + Host durable tab descriptors:
     - First by `(index, url)` (exact match — disambiguates duplicate URLs deterministically).
     - Fallback by URL multiset if a tab was opened/closed in the last 2.5 s before a `SIGKILL` shifted indices.
     - Unmatched extra Chromium tabs (e.g., `chrome://newtab/` on a brand-new profile) are closed; unmatched Host durable tabs stay dormant and open by URL on click as today.
  6. Restored tabs with `status === "unloaded"` or `discarded === true` enter `SurfaceLedger` directly in the **`suspended`** state with their `discardedPage` handle — zero eager wake storm on 70 tabs!
- **Security isolation (`SessionCdpRouter`):** `packages/browser-core/src/portable-session-cdp-router.ts` already filters `Target.getTargets` and `Target.attachToTarget` to session-claimed `page` targets only, so agents cannot see or attach to the helper extension's `service_worker` target. As defense-in-depth, add a 1-line guard in `PlaywrightContextHandle` ignoring `chrome-extension://` targets so they are never handed off to `SurfaceLedger` or `whole-context` CDP.

### 5.3 What Stays Unrestorable (Plain Words for a Person)
For `packages/client/src/host/browser-sleep.ts` (matching its calm, single-line voice):
- **After a normal tab sleep (discarded and woken):** Almost everything comes back (scroll, typed form fields, back/forward history, sign-ins). Plain note only if a page fails or had rich-text edits: *"This page reloaded to save memory. Any unsent text in rich editors or live playback started fresh."*
- **After a cold browser restart (24h asleep, host restart, update, or Restart browser):**
  - Tabs restored via Session Restore reload their page cleanly with scroll, standard form inputs, back/forward history, and sign-in kept: *"This page reloaded because your browser restarted."* (Existing copy already fits!)
  - Things that **never** come back after a sleep-discard or cold restart, in plain words:
    - **Rich-text editors (`contenteditable`):** unsent drafts in webmail/doc editors that do not auto-save to the server.
    - **Passwords typed into a form** (Chromium strips password fields for safety).
    - **Live state in memory:** paused/playing video or audio position, active calls, open WebSockets/streams, unsaved canvas/whiteboard drawings, in-progress file uploads (uploads and playing media are kept awake during tab sleep, but cannot survive a cold browser restart).
    - **Form submission results (POST pages):** after a cold restart Chromium shows a reload confirmation (`ERR_CACHE_MISS`) instead of silently resubmitting an order or payment.
    - **The last ~2.5 seconds before a sudden crash (`SIGKILL`/OOM):** a brand-new tab or edit made right before a crash may not have flushed to Chromium's session log yet.

## 6. What Is Explicitly Unverified

1. **Real Linux kernel & container behavior (all runs were on macOS arm64):**
   - Linux cgroup v2 memory accounting (`RssAnon`, `PSS`, `memory.current`) for 70 discarded tabs and 70-tab cold restart inside `deploy/home/compose.yaml` (`mem_limit: 4g`, `memswap_limit: 4g`).
   - Chromium Linux seccomp profile (`deploy/container/chromium-seccomp.json`) compatibility with `--enable-features=WebContentsDiscard` and `--load-extension` / MV3 service worker startup.
   - Option D swap/zram behavior on real Linux (compression ratio, page-in wake latency, OOM behavior under cgroup v2 `memory.swap.max`).
   - `PlaywrightChromiumLauncher` Linux `/proc/<pid>/smaps_rollup` `rendererUsage()` implementation and exact container headroom under `TabSleeper`.
2. **Playwright `1.62.1` `launchPersistentContext` interaction with restored unloaded tabs:**
   - Our prototypes drove Chrome for Testing `151.0.7922.34` directly over `--remote-debugging-pipe` (identical pipe & flags, without Playwright's JS wrapper). How Playwright's `CRPage` / `CRBrowserContext` reacts when Chromium starts with 70 restored `unloaded` tabs (e.g., whether Playwright tries to `Page.enable` / `Runtime.enable` on every restored target at startup and accidentally wakes them!) **must be verified** before shipping. If Playwright eagerly attaches to restored targets, either a tiny patch to `patches/playwright-core@1.62.1.patch` or driving native Chromium targets directly via CDP (bypassing Playwright page auto-attach for unloaded tabs) will be needed.
3. **Real-world complex websites:**
   - Our fidelity matrix used clean local HTML/JS fixtures (`/article`, `/form`, `/spa`, `/session-storage`, `/post-result`, `/beforeunload`, `/media`, `/heavy?mb=4`). Real SaaS SPAs (Gmail, Notion, Google Docs, Figma, Slack, GitHub) vary in how much state they keep in Blink form controls/`sessionStorage` vs. JS heap/`contenteditable`/IndexedDB, and have larger per-tab memory footprints than 4 MiB.
4. **Long-duration soak & `WebContentsDiscard` stability across future Chromium upgrades:**
   - `kWebContentsDiscard` is gated behind a feature flag on desktop in Chromium `151.0.7922.34` (`content/public/common/content_features.cc:370`). Repeated discard/wake cycles over hours on Linux (including frames with iframes, OOPIFs, WebWorkers, and active downloads/dialogs) were not soak-tested.
5. **Multi-window or incognito/guest contexts:**
   - All experiments tested a single default native profile window; `TabSleeper` host-retirement paths for `fresh`/guest profiles were only inspected in code, not prototyped.
