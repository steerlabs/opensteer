# Hosted teams

A hosted team is the self-hosted [team server](teams.md) run by Opensteer: one Kubernetes
namespace `team-<slug>` in the `teams-1` cluster holding Postgres, the team Host and its gateway
in one pod, served at `https://<slug>.teams.opensteer.com`. Opensteer's operators can technically
read what a hosted team stores; the create page says so. Everyone's agents still run on their own
computers, exactly as with a self-hosted team.

## Who decides what

Account decides which teams should exist; [apps/team-provisioner](../apps/team-provisioner) pulls
that list and makes the cluster match. Account never holds cluster credentials. Its provisioner
API admits only a Google-signed ID token for the service account in
`OPENSTEER_HOSTED_TEAMS_PROVISIONER_EMAIL`, with Account's public URL as audience; without that
setting Account offers no hosted teams. Wire shapes, slug rules, reserved names and the
three-team cap live in
[hosted-teams.ts](../packages/control-plane-protocol/src/hosted-teams.ts).

The first-owner setup token is generated by Account and shown once to the creator's browser;
Account stores, and the provisioner sees, only its digest. A new setup link bumps the setup
generation, which restarts the Host with the new digest. It opens setup only while nobody has
claimed the team, so Account stops offering it once a Deployment exists at the team's address.

Addresses never change and are never reused: a deleted team's row stays as a tombstone, so
cookies, bookmarks and links to an old team never reach someone else's. Deleting a team also
removes the Account Deployment its owner adopted there. Deleting an Account deletes the teams it
created, and its deletion page lists them.

## Isolation

Each team namespace runs under the `restricted` Pod Security level with no service-account
token. Its NetworkPolicy admits only the shared edge namespace `opensteer-teams-edge` on port 80
and lets pods reach DNS and the public internet, never private ranges or the metadata server;
GKE's Cloud DNS answers on the metadata address, so only its port 53 is open. Every object the
provisioner changes in a team namespace is named `team`, and its RBAC can read or change nothing
else there.

## Releases

Hosted teams follow Stable. Publishing a Stable runs the `team-provisioner` job in
[release.yml](../.github/workflows/release.yml), which deploys the provisioner with that release's
team Host and gateway digests. New teams start on them; existing teams move one at a time. A
team on the new release that is not ready holds the rest where they are, across provisioner
restarts, and is reported failed after ten minutes. Restarts a team asked for itself (a new
setup link, suspension, resuming) are never held.

Outside this repo, the GitHub environment `teams` is the only caller the Workload Identity
provider `github-teams-deployer` in `opensteer-admin`'s `github` pool admits. Its service
account, `gha-teams-deployer@opensteer-admin`, may apply only
[deploy/team-provisioner](../deploy/team-provisioner) in `teams-1`, including its ClusterRole;
the job pushes the provisioner image to GHCR with the workflow's own token. The provisioner's Kubernetes
service account impersonates `team-provisioner@opensteer-prod`, which needs no IAM roles: it
exists to sign ID tokens. The GHCR package `opensteer-team-provisioner` must be public, like the
team images, because the cluster pulls without credentials.

## Abuse

Operators suspend, resume or delete a team from inside an Account pod with
`node dist/hosted-team-operator-main.js suspend <slug> <reason>`, `unsuspend <slug>` or
`delete <slug>`. A suspended team scales to no pods and keeps its data; its creator sees that
Opensteer suspended it and can still delete it.
