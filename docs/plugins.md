# Plugins

Opensteer decides authority; the plugin engine executes the work. The personal Host owns access
settings, account consent and Requests. Team servers never run the engine or receive private
credentials. Discovery grants no authority: calls, resumes and background work check current access
again ([authority](../apps/host/src/plugins/plugin-authority.ts)). A read-only setting trusts each
tool's query label; it cannot prove what that plugin's code does. Schedules, workflows and
webhook handlers have no read-only contract and require standing `all` access, including at each
background execution. Read-only or off access still permits reading resource state and stopping,
disabling or removing background work; starting or enabling it through agent tools requires `all`.

## Process and storage

The Host supervises a private child that starts on demand and stops when idle. Programs run away
from the event loop serving clients; workerd belongs to that child's lifetime. Saved schedules can
wake it again ([demand](../apps/host/src/plugins/engine-storage.ts)). Opening Plugins never waits
for a start: the installed list goes out with local tools and no plugins, and a
`host.plugins-changed` notice follows once the engine can answer, so every client must re-read on it.

Paused programs live in memory. After a Host restart or child loss, unfinished executions become
interrupted and their Requests are cancelled. Earlier calls may already have taken effect. Never
rerun the program to recover it; the agent must inspect the outcome before deciding what to do.
Answering a Request and driving its continuation are separate operations, owned by the
[execution coordinator](../apps/host/src/plugins/plugin-executions.ts).

Engine tables live in the Host database's `plugin_engine` schema, separate from Host migrations.
The engine also keeps repositories, builds and per-plugin SQLite data under the Host data
directory. With the Host, engine and sandbox stopped so all writers are quiet, back up the database, those files and the Host credential key together; restoring only
one part loses the relationships or the ability to decrypt credentials. Activating an earlier
version changes code, not plugin data.

Agents read workflow and schedule history newest first, a page at a time. Run outputs reach only
the person's own tasks, and only while the plugin is on; a connected external agent, or any caller
while it is off, sees what ran, when and how it ended.

The vendored tree is generated by [the import command](../scripts/plugin-engine/import.mjs).
Change copied code through numbered patches in `scripts/plugin-engine/patches`, then regenerate
it; hand edits disappear on the next import. Product authority and Host-specific behavior belong
outside that tree.

## Accounts and local tools

Consent belongs to each plugin's account link, even when two plugins use the same saved account.
It pins the reviewed requirement, sites and credential exposure; a declaration that widens access
needs consent again. Linking trusts plugin setup code before per-tool approval. Providers without
declared hosts and older framework protocols can expose real credential values; sealing is not a
blanket guarantee. [Plugin accounts](plugin-accounts.md) explains sign-in and return authority.

Device data apps and local servers share the tool namespace through Host providers, without
building wrapper plugins. Listings reflect the owning computer's state, and calls never move to
another computer. Native device contracts and Runner wire names stay unchanged. Computer use
keeps its own sessions and approvals ([computers](computers.md)).

## Pages, callbacks and skills

A page opens through an owner viewing reference. The client obtains a private viewing URL through
the existing app gateway; that URL never belongs in agent output or saved navigation state. Pages
act with the owner's standing plugin access and current account links, not a Run's authority.
Approval-requiring page operations fail as they do in the engine; they do not pause for Needs you
([Apps](apps.md)).

Public webhooks use the Host's bounded callback route, which preserves original body bytes for
signature checks. Local-only Hosts cannot advertise a public callback. A changed public origin
requires reconnecting an existing provider subscription; Opensteer cannot silently change the
provider's saved URL. Manual webhook removal requires cleanup at the provider followed by the
person's confirmation before plugin removal can finish.

Packaged text skills at the active version are cached for native agent delivery. Run planning reads
that cache and verifies its version without starting the child. Turning plugin access off excludes
its skills. Dynamic skills are read through `plugin_skills`, and binary skill resources do not enter
the native cache ([skill cache](../apps/host/src/plugins/plugin-skill-cache.ts)).

## Runtime support and cost

The sandbox has its own platform requirements. The pinned macOS arm64 binary declares macOS 13.5,
while the desktop app advertises 13.0. The Host keeps running when the sandbox cannot load and
reports a structured unavailable reason, including the binary's declared minimum when readable.
Tim must decide before release whether to select a sandbox supporting the app's floor, raise the
app floor, or explicitly support Plugins only on newer systems. This change does not decide it.

Budget hundreds of MiB unpacked and tens of MiB of additional download. A running engine and sandbox can retain roughly 0.6 GiB idle and around 1 GiB after one hermetic plugin build/call; those post-build samples exclude the complete Host and are not peak-memory qualification.
The selected external payload measures about 133 MiB unpacked and 35 MiB gzip on macOS arm64.
The whole-subsystem packaging estimate is about 166 MiB unpacked and 42 MiB of isolated ZIP contribution, not a
complete signed-app measurement. Resident memory varies with loaded plugins and builds; the
engine is stopped when idle. Re-measure the final runtime with the
[desktop procedure](../.agents/skills/desktop-builds/references/plugin-runtime.md) before choosing
supported-device budgets; earlier pre-reduction memory samples are not current qualification.
