# Automation program contract

Automation programs execute as Node.js ESM modules (Node 24 or newer) on the hosting computer, with Agent home as the working directory, so relative paths and relative imports resolve from Agent home. The source must export one default function (async or not): The program object must declare toolContractVersion: use 4. Use computer_list for computers, opensteer_ai_account_list for AI accounts, and opensteer_task_send or opensteer_task_delegate for tasks. `export default async function ({ event, capabilities, opensteer }) { ... }`. `event` is frozen ({ id, payload, receivedAt, source, trigger }); `event.source.kind` is "schedule" (with scheduledFor), "webhook" (with method, headers, and optional deliveryId), "manual" (a manual run carries only the payload), or "watch" (the single startup event for a continuous watch). A watch program runs continuously and must not resolve; Opensteer restarts unexpected exits with exponential backoff and pauses the automation after three consecutive unexpected exits. `capabilities.mcp` is the short-lived Opensteer MCP endpoint ({ url, token }); `capabilities.browserCdp` is a short-lived CDP WebSocket endpoint ({ url, token }) or null when no browser access is available. For a watch, every non-null capability also has expiresAt. Watch capabilities rotate while the process runs: call `opensteer.capabilities()` for the current values, and reconnect an expired CDP session with its current browserCdp value. `opensteer.callTool(name, input)` calls any Opensteer tool, including integration tools already granted to the owner. Supply a stable observationId with each watch call to opensteer_task_send or opensteer_task_delegate; when omitted, the request ID is used. Opensteer deduplicates the ID and admits up to 120 independent observations per activation per hour. Node built-ins (node:fs, node:child_process, ...), fetch, and packages installed in Agent home's node_modules are available; Deno, Bun, and DOM globals such as window and document do not exist, and nothing installs packages automatically. TypeScript runs through Node's built-in type transform: type annotations, enums, and namespaces work; tsconfig paths, decorators, and JSX do not. For schedule, webhook, and manual runs, the awaited return value serialized as JSON (at most 512 KiB) becomes the occurrence result, and a thrown error fails the occurrence with its message and stack. Their console output is captured as stdout and stderr (512 KiB each); watch stdout and stderr retain only their latest 16 KiB tails. A program acts as its task: its Opensteer tool calls use that task's access-mode ceiling, and only a full-access agent can write one.

`event.trigger` is `{ id, revisionId, anchorThreadId }`: `id` is the automation ID and `anchorThreadId` is its task's ID, which you pass as `taskId`.

Choose the destination before writing the program: reminders stay in the asking task; ongoing monitors use `opensteer_automation_create` with `ownTask: true`; a program uses `opensteer_task_create` for a new listed task per run. Check in code first and persist state under `automations/<automation-id>/` in Agent home. A model check queues the monitor's task with `freshContext: true` and carries its criteria, report destination and state path each time. Start child checks from that monitor task. Send real finds to the asking task with `opensteer_task_send` delivery `queue` (a `report` never notifies) or email through a connected integration. Each background wake briefly says what happened.
