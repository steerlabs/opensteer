# Verify and maintain

Verify changed knowledge and helpers in a way that cannot damage the person's working state. Read
back changed instructions and check linked paths; choose safe checks that establish the useful
behavior. Use fixtures or a side-effect-free mode when a check would repeat an external action.
Never break the person's page, files or setup to test a recovery path; reproduce the failure in your
own tab, a copy or a fixture, and use a fixture or isolated session when another tab would share the
state being changed. Keep an untested approach labeled as such; an attempted action is not evidence
of success.

Preserve other Threads' work: reread shared files before editing, make focused changes, and avoid
overwriting unrelated state. Remove or update obsolete guidance when the user changes direction.
Summarize material capability changes or remaining blockers without narrating every file operation.

Files alone do not grant access, create a Trigger, or keep a process alive. If recurring work was
requested, any agent can use `opensteer:triggers` to establish it within its authority and verify
the returned state. An agent that lacks the required authority reports the concrete requirement to its assigner or the person through its task.
