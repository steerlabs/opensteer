# Trigger program contract

Trigger programs execute as Node.js ESM modules (Node 24 or newer) on the anchor Thread's Runner, with Agent home as the working directory, so relative paths and relative imports resolve from Agent home. The source must export one default function (async or not): The program object must declare toolContractVersion: use 3 for new programs. Use environment_list for computers and orchestrator_capabilities for engines and models. `export default async function ({ event, capabilities, opensteer }) { ... }`. `event` is frozen ({ id, payload, receivedAt, source, trigger }); `event.source.kind` is "schedule" (with scheduledFor), "webhook" (with method, headers, and optional deliveryId), "manual" (a manual run carries only the payload), or "watch" (the single startup event for a continuous watch). A watch program runs continuously on the anchor Thread's machine and must not resolve; Opensteer restarts unexpected exits with exponential backoff and pauses the Trigger after three consecutive unexpected exits. `capabilities.mcp` is the short-lived Opensteer MCP endpoint ({ url, token }); `capabilities.browserCdp` is a short-lived CDP WebSocket endpoint ({ url, token }) or null when no browser access is available. For a watch, every non-null capability also has expiresAt. Watch capabilities rotate while the process runs: call `opensteer.capabilities()` for the current values, and reconnect an expired CDP session with its current browserCdp value. `opensteer.callTool(name, input)` calls any Opensteer tool, including integration tools already granted to the owner. Supply a stable observationId with each watch call to thread_send or delegate_task; when omitted, the request ID is used. Opensteer deduplicates the ID and admits up to 120 independent observations per activation per hour. Node built-ins (node:fs, node:child_process, ...), fetch, and packages installed in Agent home's node_modules are available; Deno, Bun, and DOM globals such as window and document do not exist, and nothing installs packages automatically. TypeScript runs through Node's built-in type transform: type annotations, enums, and namespaces work; tsconfig paths, decorators, and JSX do not. For schedule, webhook, and manual runs, the awaited return value serialized as JSON (at most 512 KiB) becomes the occurrence result, and a thrown error fails the occurrence with its message and stack. Their console output is captured as stdout and stderr (512 KiB each); watch stdout and stderr retain only their latest 16 KiB tails. A program acts as its anchor Thread: its Opensteer tool calls use its access-mode ceiling, and only a full-access agent can write one.

Choose the destination before writing the program: reminders stay in the asking task; ongoing monitors use `trigger_write` with `ownTask: true`; a program uses `delegate_task` with `standalone: true` for a new listed task per run. Check in code first and persist state under `automations/<trigger-id>/` in Agent home. A model check queues the monitor's task with `freshContext: true` and carries its criteria, report destination and state path each time. Start child checks from that monitor task. Send real finds to the asking task with `thread_send` delivery `queue` (a `report` never notifies) or email through a connected integration. Each background wake briefly says what happened.
